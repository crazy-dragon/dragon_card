星际航行日志 · Voyage Log
========================================

【这是什么】
**一张卡 = 一天**，卡里放着"那天生效的打卡目标"（例如"每日20分钟美剧""阅读10页"）。
默认铺 2026-08-06 → 2027-10-31，共 452 张（一天不落）。
用**小工具**（voyage-log）打开卡组：

  · 月历看历史 —— 有记录的日子亮起星点，点亮的星数 = 那天记了几项；
    今天那一格在月历上有高亮框；
  · 点某一天 → 弹出那天的卡面，今天那张可以直接点任务行记一笔；
  · 记一笔 = 向宿主写一条埋点（movie_20min / read_10pages），卡片自己不存状态。

【卡片模型】
  {"item_order": 1, "data": {"date": "2026-08-06", "tasks": [ {action,label,hint,icon} ]}}

  · item_order / date —— 线性升序，`item_order = N` ⟺ `date = 首日 + (N-1)`
    （工具按 date 排月份，不依赖服务端的队列顺序）
  · tasks —— **那天生效的目标快照**，不是一个全局清单

【为什么目标写在每张卡里】
模板与工具是**跨卡组共享**的，只有**卡片数据是卡组私有的**。
旧版把任务清单写在模板里 ⇒ 改一次目标，所有打卡卡组一起变、历史也跟着变样。
现在目标随卡片固化：改目标只影响"那个月及以后"，历史月份保留当时的快照，也不牵连别的卡组。
（同理，小工具里**不要**写死任务清单或月份数量 —— 一切从卡片数据来。）

【外观】
卡面**只有「今天」那张换装**，而且是恒为深空暗色 —— 不跟随应用的全局明暗模式。
  理由：一眼就能从月历/卡面里认出"今天"。
  深空底 + 星尘点阵 = 夜空；顶部渐变条 = 星轨；完成任务 = 点亮一颗星（暖金）；
  最近 7 天 = 航迹上的 7 个节点；连续天数 =「航行第 N 天」；
  头部右侧的黑洞 = 今天的印记（吸积盘 + 引力透镜环，纯 CSS 动画，无 canvas / 无 rAF）。
历史日 = 素净浅色，未来日 = 淡紫未解锁。

外壳有两套皮肤，**默认素白（浅色）**：浅底上"今天的深空卡"才跳得出来；
整页深色会让它贴底不跳，反而最浅的历史卡最抢眼。星夜保留为可选。
（记忆在 localStorage；`SKINS` 里素白在前。）

【怎么用】
1. 管理卡组 → 上传数据 → 选 cards.json（**日卡**，唯一必需的输入）
2. 管理卡组 → 小工具 → 上传 voyage-log.zip 并绑定
3. 点卡组进入小工具（全屏新开一页）：默认停在当月；点月历任意一天看那天的卡面；
   今天那张可以点"点亮"记一笔（点两下确认，防误触）。
   月份在"目录"里点，点一次开一个页签，再点页签才切过去（与本体一致）。

【改目标 / 加任务 / 改范围】
打开 `_src/build.py`，在 GOALS 里**追加**一条（或在命令行给范围），然后重跑：

    GOALS = [
        {'from': '2026-08', 'tasks': [MOVIE]},          # 8 月起：只看美剧
        {'from': '2026-09', 'tasks': [MOVIE, READ]},    # 9 月起：加读书（往后覆盖）
    ]

    python3 _src/build.py                                     # 重写 cards.json（默认铺到明年十月末）
    python3 _src/build.py --start 2026-08-06 --end 2027-10-31  # 显式指定范围
    再上传一次 cards.json 即可（历史埋点不受影响）

· `from` 是生效月份（含当月）→ 只覆盖"后续的数据"；历史条目**不要删**，它们是旧月份的快照来源。
· action 是埋点动作名（英文小写 + 下划线），历史记录靠它归属：
  改了字 = 老记录不再算作这个任务，所以确定之后再改。label / hint 随便改，只影响显示。
· 默认范围 = `HISTORY_START`（2026-08-06，打卡历史首日）→ **明年十月末**（一次铺满，年内不用重建）。

【统计口径】
· 打卡写成埋点事件（action = movie_20min / read_10pages）。
· 月历上的星点、"航行第 N 天"、最近 7 天航迹，全部由 `/v1/observability/data`
  的 heatmap 实时算出，工具自己不存任何状态。
· heatmap 只回溯 **[今天-364 天, 今天]**，更早的月份会显示"还没有记录"。
· 只要当天有任意一条目标对应的打卡事件，这天就算"活跃"。

【文件说明】
  cards.json         日卡列表 [{item_order, data:{date, tasks[]}}, ...]（452 张）
  tool.zip           小工具打包产物（== dragoncard_tools/dist/voyage-log.zip）
  meta.json          版本 / 作者 / 许可（含 tool 字段指向工具）
  LICENSE            DragonCard Data License v1.0
  _src/build.py      卡片数据生成脚本（改目标 / 改范围改这里）
  template.json      旧模板定义（**已废弃**；模板已从卡组解绑，仅留档）

【历史沿革（为什么是日卡）】
  2026-09：曾试过"一个月一张卡"（14 张月卡）—— 卡片数少、目标按月快照。
  但它有个硬伤：**一张月卡订不了"这天记没记"**，而且和数据本来的样子（一天一条记录）对不上。
  2026-09-26 回到**日卡**：452 张，一天一张；目标快照的机制**保留**（写在每天那张卡的
  `data.tasks` 里），所以"改目标不翻旧账"这个好处没有丢。
  迁移时清掉了 389 行陈旧 progress（旧 403 张日卡的残骸，指向了后来被 deck 30/31/32
  复用的 id），57 条埋点一条没动 —— 记录在库里按 created_at 聚合，不 join 卡片表，
  所以重建卡片永远不影响历史。

【小工具在哪】
  dragoncard_tools/voyage-log/          源码（index.html + assets/）
  dragoncard_tools/dist/voyage-log.zip  打包产物（由 dragoncard_tools/build.py 生成）
  原地更新（**别重复导入**，否则会多出一个 t_tool 行）：
      python3 dragoncard_tools/build.py voyage-log
      POST /v1/tools/<id>/replace   -F zip=@dist/voyage-log.zip
