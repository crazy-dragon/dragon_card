星际航行日志 · Voyage Log
========================================

【这是什么】
一张卡 = 一天，卡里可以放多个打卡任务（例如"每日20分钟美剧""阅读10页"）。
点一下任务行就写一条埋点，卡片自己不保存任何状态——
今天是否活跃、连续多少天、最近 7 天、几点记录的，全部从埋点统计实时读出来。

【为什么这样设计】
· 卡片数据里只有一个字段 date，其它什么都不用存 → 换目标不用动数据。
· "记录"就是一条简短埋点（movie_20min / read_10pages），谁在什么时间做了什么，一目了然。
· 旧版打卡卡组适合"单一任务"，这个版本适合"多个任务 + 目标经常换"。

【外观：星际航行 · 星夜版】
· **只有"今天"那张卡换装**，而且是恒为暗色——不跟随应用的全局暗色模式。
  理由：一长串素卡里，深色是唯一能一眼认出"今天"的信号。
  星夜底 + 星尘点阵 = 夜空；顶部渐变条 = 星轨；完成任务 = 点亮一颗星（暖金）；
  最近 7 天 = 航迹上的 7 个节点；连续天数 =「航行第 N 天」；
  头部右侧的黑洞 = 今天的印记（吸积盘 + 引力透镜环，纯 CSS 动画，无 canvas / 无 rAF）。
· 历史卡 / 未来卡保持素净原样，混在 400 张的长列表里不吵。
· 全部写在 cardCss（以 .ci-today 与 .bh 开头）与 cardJs 的 render() 里，
  只是模板层——不碰数据、不碰应用本体。不想要这个外观，删掉 card.css 里
  「星际航行 · 星夜版」与「黑洞」两段、以及 render() 里注入 .bh 的那 5 行即可。

【怎么用】
1. 管理卡组 → 上传模版 → 选 template.json
2. 管理卡组 → 上传数据 → 选 cards.json（或 cards_single.json，见下）
3. 进入学习页：今天那张卡直接点任务行即可记录；昨天/更早的卡只读；未来的卡未解锁。

【改任务清单】
打开 template.json，找到 cardJs 里的 TASKS 数组，增删改即可：

    var TASKS = [
        { action: 'movie_20min',  label: '每日 20 分钟美剧', hint: '看一集，20 分钟', icon: 'fa-tv' },
        { action: 'read_10pages', label: '阅读 10 页',       hint: '读完 10 页记一笔', icon: 'fa-book-open' }
    ];

· action 是埋点动作名（英文小写 + 下划线），历史记录靠它归属：
  改了字 = 老记录不再算作这个任务，所以确定之后再改。
· label / hint 随便改，只影响显示。
· 改完重新上传模版即可，**数据不用动**，历史记录不会丢。

【两种卡片模式】
· cards.json        403 张：**按日期线性升序**（第 1 张 = 最早一天，最后一张 = 明年今天）。
                    开关卡组时会自动滚到"今天"那张；往上一张是昨天、往下一张是明天（未解锁）。
                    卡片按每页 100 张分页（P001 = 第 1~100 天，共 5 页）。
                    时间轴一次铺满一年，一年内不用重建；想换范围就重跑
                    `python3 _src/build.py --start 2026-08-06 --end 2027-09-12`
                    再重新上传 cards.json。
· cards_single.json 只有 1 张、没有日期的卡 = 永远是"今天"，永久零维护。
                    历史去统计页看（那页本来就是按天聚合的热力图）。

【统计口径】
· 打卡会写成埋点事件（action = movie_20min / read_10pages）。
· 统计页热力图 = 每天的事件次数；"连续天数 / 最近 7 天"由卡片实时算出。
· 只要当天有任意一条打卡事件，这天就算"活跃"。
